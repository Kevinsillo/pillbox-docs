This page takes you from a fresh install to a working Pillbox setup — binary installed, MCP connected, and your first bottle registered.

## Prerequisites

- `pillbox` binary installed ([installation guide](/getting-started/installation/))
- Claude Code or another MCP-compatible AI assistant

## Setup

<Steps>
1. Initialize a bottle in your project directory

   ```bash
   cd your-project
   pillbox bottle init
   ```

   The wizard asks for a display name and scope (`local` or `global`). Choose `global` if you want this project's knowledge accessible from anywhere.

2. Install the MCP server

   ```bash
   pillbox mcp install
   ```

   This installs the Node.js MCP server to `~/.pillbox/mcp/` and registers it with your AI agent. The command asks which provider to configure (Claude Code or OpenCode) — or pass `--provider claude|opencode`.

3. Install the agent skill

   ```bash
   pillbox skill install
   ```

   This installs the Pillbox skill to your AI provider's global config folder (`~/.claude/skills/pillbox/` for Claude Code, `~/.config/opencode/skill/pillbox/` for OpenCode), which guides the agent to use Pillbox tools correctly. With more than one provider installed, the command asks which to target — or pass `--provider claude|opencode`.

4. Restart your AI agent (Claude Code or OpenCode)

   Run `/mcp` to confirm `pillbox` is connected and its tools are listed.

5. Verify everything works

   ```bash
   pillbox status
   ```

   You should see the binary, global DB, MCP server, and skill all reported as active.
</Steps>

## Your first session

Once setup is complete, Claude uses Pillbox automatically. At the start of a new session it retrieves recent context via `bottle_context` and `prescription_context`. As it works, it saves pills for decisions and discoveries. At the end, it saves a session summary.

You don't need to do anything — the skill handles the workflow.

## Review what your agent saved

Start the web UI to browse pills, capsules, and prescriptions:

```bash
pillbox serve start
```

Then open `http://localhost:4242` in your browser.

The UI is a supervision layer — use it to spot entries that are redundant, wrong, or poorly written and correct them. The agent handles all writes during normal work.
